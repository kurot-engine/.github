# Security Policy

## Reporting a vulnerability

Please do not disclose security vulnerabilities in public issues,
discussions, pull requests, or social media.

Use the **Report a vulnerability** button in the affected repository's
Security tab to submit a private GitHub Security Advisory. Include:

- the affected repository, package, and version;
- a clear description of the impact;
- reproduction steps or a minimal proof of concept;
- affected browsers or environments;
- any known workaround or mitigation.

Reports will be reviewed as availability permits. You may be asked for more
information before impact and remediation can be confirmed. Please allow time
for a fix and coordinated release before publishing details.

## Supported versions

Security fixes normally target the latest published version of each package.
Older package lines may require upgrading unless a repository documents a
different support policy.

## Scope

Security reports should describe a concrete security impact. General bugs,
rendering defects, performance problems, and feature requests should use the
repository's normal issue templates.
